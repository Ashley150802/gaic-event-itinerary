How It Works

A technical deep dive into every subsystem in Surket.

1. Storage Layer

The Store Interface

The Store interface (server/src/types.ts) is the single contract between business logic and the database. It defines ~30 methods covering CRUD for events, segments, surveys, questions, and responses, plus analytics helpers.

SQLite Driver (Node)

sqliteStore.ts implements Store against Node's built-in node:sqlite module. No native modules needed — ships with Node 22.5+. Schema is applied lazily on first init() call.

D1 Driver (Cloudflare)

d1Store.ts implements the same interface against Cloudflare D1's prepared statement API. Same portable SQL — no dialect differences.

Schema

Six tables, all portable SQL:

events → segments (itinerary, ordered by position)
events → surveys → questions (ordered by position)
       surveys → responses → answers (keyed by question_id)

Foreign keys use ON DELETE CASCADE for segments, questions, responses, answers, and ON DELETE SET NULL for the survey→event relationship.

3. Live Tally System

The live tally system enables real-time result streaming. The useLiveTally.ts React hook encapsulates both transports behind a single API.

Version-Based Polling

The version field on SurveyResults is the monotonic cursor. The polling fallback only re-renders when version increases, preventing flicker.

4. Template System

Templates in templates.ts define pre-built event + survey blueprints. When instantiated, the template engine creates all entities in a single transaction.

5. Frontend Router

A custom History-API router (router.tsx) handles SPA navigation without react-router. Routes are defined in App.tsx as a simple path→component map.

6. Settings & Theme System

All operator preferences live in localStorage under key surket.settings:

  • Theme: 5 accent palettes (Aurora, Ember, Forest, Violet, Rose)
  • Color mode: Dark / Light / System
  • Density: Comfortable or Compact
  • Reduce motion: Disables animations for accessibility
  • Presentation settings: QR visibility, font scale, percentage display

7. Security Stack

Six middleware layers applied in order: request logger → security headers → CORS → body size limit → rate limit → admin token guard. Public routes (reading, submitting responses) bypass the token check.
